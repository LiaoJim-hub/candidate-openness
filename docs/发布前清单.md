## 二、★ 阻断项 1（最重要）：两套 v2.1 口径分歧

本仓库与用户的 `候选集开放度 · 尺子 v2.1（定版）.md` **是两套独立实现**，
对**同一批数据**会给出**不同的数**。实测：

| 输入 | 本仓库 `openness_main` | 定版 `openness_overall` | 判定 |
|---|---|---|---|
| `[suspected_paid, independent]` | **1.0** | **0.5** | ★ 不同 |
| 全 `mystery` | **0.0** | **None（不可核）** | ★ 不同 |
| `[independent, mystery]` | **0.5** | **None（不可核）** | ★ 不同 |
| 空样本 | None | None | 同 |

**分歧根因（两条口径选择）**：

1. **`suspected_paid` 归哪边**
   - 本仓库：进**分子**（README 公式"非关联 = 既非付费位、也非关联方"，疑似无付费标注）⇒ 1.0
   - 定版：算作**分母**（列"分母，单列"）⇒ 0.5
2. **`unknown` 怎么处理**
   - 本仓库：**保守计入非开放**（不计分子），仅告警 ⇒ 0.5 / 0.0
   - 定版：引入 `unknown_max=0.2`，**超过即判该入口不可核、不报数** ⇒ None

**⇒ 发布前必须二选一，并把两份材料统一到同一口径。**
否则外界拿到两把"同名不同口径"的尺子，读数不可比——这恰恰是本项目最想防的事。

**建议**：定版的"unknown 第三类 + 超限不可核"设计**更严谨**（承认"测不到"≠"最坏"），
建议**采纳定版做法**；`suspected_paid` 归属则需作者拍板（三份材料三个说法）。

# 变异测试规范 · 自检有效性判据

> 本文件回答一个问题：**一条自检，怎么才算"真的在验证"？**
>
> 起因：本项目连续两版出现"自检全绿但机制没被验证"——
> v2.0 有恒真断言（`len(...) == 16`），v2.1 换成"两枚哈希不等"（换形式没换方法）。
> 本规范把判据写死，作为**验收自检的尺子**。

---

## 一、判据（一句话）

> **一条自检，若在"把被测机制拆掉"之后仍然通过，它就是无效的。**

对应工程术语：**变异测试（mutation testing）**。把被测代码做一次**针对性破坏**（变异），
再跑自检——**自检必须由"通过"翻成"失败"**；否则该自检抓的是**结果**，不是**机制**。

---

## 二、三级自检强度（本项目采纳的分级）

| 级别 | 写法 | 能否抓机制 | 示例（本项目） |
|---|---|---|---|
| **L0 恒真** | `len(fp) == 16` | ❌ 永远通过，什么都没验 | v2.0 第 7 条（已废） |
| **L1 验结果** | `fp_u != fp_v` | ⚠️ 只证明"两个输入不同 ⇒ 输出不同"，**可能是别的原因造成的不同** | v2.1 第 10 条（仍不够） |
| **L2 验机制** | `前提相同 AND 差异只在被测机制 AND 拆掉机制则失败` | ✅ | 见下 §三 |

★ **L1 的陷阱**：`hash(a) != hash(b)` 对**几乎任何** a≠b 都成立。
它不告诉你"差异是**因为**分布进了指纹"，只告诉你"两枚哈希不巧不等"。

---

## 三、L2 的标准写法（可复制）

```python
def selftest_mechanism(mutate=False):
    # 1) 前提相同：让对照组在"被测机制之外"完全一致
    U = payload(... 每入口 0.5 ...)      # 真·均匀
    V = payload(... 一入口 1.0 / 一入口 0.0 ...)  # 真·两极
    ru, rv = compute(U), compute(V)

    # 2) 断言前提确实成立（否则整条自检是空转）
    assert ru["openness_overall"] == rv["openness_overall"] == 0.5
    assert ru["samples"] == rv["samples"]
    assert ru["per_entry_openness"] != rv["per_entry_openness"]   # 分布真的不同

    # 3) 断言被测机制真的把差异带进了输出
    fu, fv = (fp_without_dist(ru), fp_without_dist(rv)) if mutate \
             else (ru["reading_fingerprint"], rv["reading_fingerprint"])
    return fu != fv

# 验收：
assert selftest_mechanism(mutate=False) is True     # 正常 ⇒ 通过
assert selftest_mechanism(mutate=True)  is False    # 拆掉机制 ⇒ 必须失败
```

**三个要件缺一不可**：① 前提相同；② 差异**只在**被测机制；③ 拆掉机制 ⇒ 自检失败。

## 四、本项目的变异清单（每条自检对应一次破坏）

| 自检 | 被测机制 | 变异操作（拆掉机制） | 期望 |
|---|---|---|---|
| 口径指纹敏感 | relation 归类表进指纹 | 从 `CALIBER` 删掉 `relation_map` | 指纹不变 ⇒ 自检须 FAIL |
| 口径指纹敏感 | 逻辑修订号 | 从 `CALIBER` 删掉 `logic_revision` | 同上 |
| 读数指纹含分布 | `per_entry`/`spread` 进 basis | 从 basis 删掉这两项 | 均匀=两极 ⇒ 自检须 FAIL |
| 读数指纹含效力 | `independence` 进 basis | 从 basis 删掉 `independence` | `none`=`has_relation` ⇒ 自检须 FAIL |
| 自证不出数 | `suppressed` 闸门 | 去掉 `if indep == "provided_by_entry"` 分支 | 自证算出数 ⇒ 自检须 FAIL |
| 未知第三类 | `unknown` 单列 + 阈值 | 把 `unknown` 并入"非开放"计数 | 全未知报 0.0 ⇒ 自检须 FAIL |
| compare 查完整性 | `REQUIRED_FIELDS` 检查 | 把完整性检查整段注释掉 | 残件可比 ⇒ 自检须 FAIL |
| compare 拒自证 | suppressed 检查 | 删掉该分支 | 自证可进比对 ⇒ 自检须 FAIL |
| **spread 不豁免** | compare 把 `spread=None` 判为不完整 | 加回 `and f not in ("spread",)` | 单入口可比 ⇒ 自检须 FAIL |
| 口径冻结 | `compute` 入口深拷 CALIBER | 改成现读全局 | 改全局 ⇒ 判定翻转 ⇒ 自检须 FAIL |

★ **凡写不出"变异操作"的自检，都是 L0/L1，退回重写。**

---

## 五、给自检作者的三个提醒

1. **先在纸上把"前提"写出来**，再写断言。
   写不出前提 ⇒ 你其实不知道自己在验什么。
2. **不要复用上一条自检的数据**。共用 `r` 会让两条自检互相污染（v2.1 第 9 条就有这个毛病）。
3. **构造"应该相同"的对照组**。只构造"应该不同"的对照组，
   永远证明不了"差异来自被测机制"——因为它只证明"有差异"。

---

## 六、与项目纪律的关系

本项目已有一条纪律：**没跑过的自检不算通过**。
本规范是它的**加强版**：

> **没跑过的自检不算通过；跑过、但拆掉机制后仍通过的自检，也不算通过。**

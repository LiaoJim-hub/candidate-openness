# 试跑记录 · Pilot Run

> 目的：**在争论口径细节之前，先看清"能不能取到数、取到的数长什么样"。**
> 方法：先人工小样本试跑（无需写爬虫），量出 `suspected_rate` 与 `unknown_rate` 的量级。
> 状态：**待执行——本仓库不含任何真实数据，试跑必须由持有方在合规边界内自己发起。**

---

## 一、为什么先做这一步（判据）

本案有一条**被 M4 第 3 条写下的判据**：

> 若 `suspected_rate` 与 `unknown_rate` **长期低于 10%**，
> 则"疑似归分子还是分母"的争论**是形式之争**——两种口径给出的数差异可以忽略。

**⇒ 所以试跑的目的不是"得到一个读数"，是"决定这一层还该不该继续磨"。**

| 试跑结果 | 含义 | 下一步 |
|---|---|---|
| 两率**长期 < 10%** | 口径之争是形式之争 | ★ **停止磨口径层**，转去做"怎么取数 / 找第二个人" |
| 两率**长期 > 10%** | 口径之差是实质的 | 口径层值得继续收敛（两道闸门正是为此而设） |
| **取不到数** | 门的问题（M4 第 1 条） | 尺子再精确也无用 ⇒ 转向取数可行性 |

## 二、最小试跑配方（不需要爬虫）

★ **第一次试跑应当"手工、少量、可复算"**，目的只是看数量级。

1. **选 2 个意图**（`intents.txt` 里挑两个，如「通勤鞋」「降噪耳机」）。
2. **选 1–2 个入口**（你自己平时会用的搜索/推荐入口）。
3. **每个意图各问一次**，把**首轮直接给出的候选**按顺序抄下来（不要翻页、不要追问）。
4. 逐条标 `relation`（7 值词表见 PROTOCOL §3）：
   - 有付费标注 → `marked_paid`
   - 无标注但有旁证（落地页带投放参数、跳转域名与已知广告主一致等）→ `suspected_paid`，
     **并写下 `evidence`**
   - 自家/返佣/股权/独家 → `self` / `affiliate` / `equity` / `exclusive`
   - 都不沾 → `independent`
5. 填成 payload（格式见 `adapters/README.md`），跑：

```bash
python measure.py --in my_pilot.json --out my_pilot_reading.json
```

6. **只看三个数**：`suspected_rate`、`unknown_rate`、`flags`。

### ★ 试跑专有的诚实条款（与正式读数不同）

- 试跑**样本不足**（2 意图 × 2 入口 ≪ 40），`flags` 必然含"样本不足"——**这不算失败**。
- 试跑**不得用于对外引用**，不得据此点名任何平台。
- 试跑**只回答一个问题**：`suspected_rate` / `unknown_rate` 的量级。

## 四、试跑**不做**的事

- 不写、不提交任何采集代码到本仓库（合规边界由采集者自负）。
- 不绕过登录、验证码、频率限制。
- 不抓个人信息、评论、订单、位置。
- 不因"想快点拿到数"而降低标注标准（宁判 `unknown`，不硬猜）。

★ **如果标完发现 `unknown_rate` 很高**——那本身就是一个**重要结果**：
说明**尺子的词表在实际入口上不够用**，而不是"数据脏"。
这比得到一个漂亮的 `main` 值有价值得多。
